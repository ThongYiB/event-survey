# Event Survey

เว็บแอป Next.js (App Router) ใช้ TypeScript, JSX และ CSS ส่วน SQL ใช้สำหรับ PostgreSQL บน Supabase

## เริ่มบนเครื่อง

```sh
npm ci
npm run dev
```

เปิด http://localhost:3000 แล้วตรวจโค้ดด้วย `npm run lint` และ `npm run build`

## ทดลองลงทะเบียนและเช็กอิน

- ใช้ Node.js 22.13 ขึ้นไปสำหรับ SQLite
- ลงทะเบียนที่ `/attendee/register` เพื่อรับ QR ตั๋ว จากนั้นเข้า `/login` ด้วยบัญชีทดสอบ `staff@example.com` และรหัสผ่าน `1234` ในโหมด `npm run dev`
- หน้า `/staff` มีสแกน QR ค้นหารายชื่อ และรับลงทะเบียน Walk-in ผู้เข้าร่วมที่ลงทะเบียนใหม่จะอยู่ในฐานข้อมูลเดียวกับ Staff ที่ `data/event-survey.db`
- บัญชี Staff นี้ใช้สำหรับทดสอบกับอีเวนต์ตัวอย่างในเครื่อง การตั้งค่าทีมงานของ Event Manager และการยืนยันตัวตนผ่าน Supabase ยังแยกจาก SQLite
- การรัน `npm start` ปิดการเข้าสู่ระบบ Staff ทดลองโดยค่าเริ่มต้น หากต้องใช้เพื่อเดโมในเครื่อง ให้ตั้ง `STAFF_DEMO_PASSWORD` (อย่างน้อย 16 ตัวอักษร) และ `STAFF_DEMO_SESSION_SECRET` (ค่าสุ่มอย่างน้อย 32 ตัวอักษร)

## ตำแหน่งไฟล์

หน้า Admin บันทึกรายการบัญชี สถานะระงับอีเวนต์/บัญชี และ Audit Log ใน localStorage ของเบราว์เซอร์เดิม การรีเฟรชไม่คืนรายการเริ่มต้น ไม่เก็บรหัสผ่านใน localStorage และยังไม่ใช่ระบบบัญชีจริงหรือข้อมูลร่วมข้ามเครื่อง ใช้ที่อยู่เว็บเดิมเสมอ เพราะ `localhost` และ `127.0.0.1` มีพื้นที่จัดเก็บแยกกัน ตรวจพฤติกรรมด้วย `node scripts/test-admin-persistence.cjs`

- `src/app` สำหรับหน้าจอและเส้นทาง API ของ Next.js
- `supabase/migrations` สำหรับไฟล์ SQL ที่เปลี่ยนโครงสร้างฐานข้อมูลตามลำดับ

## Supabase

โค้ดเชื่อมบัญชี สิทธิ์ Admin/Manager/Staff อีเวนต์ และการมอบหมายงานเตรียมไว้แล้ว ดูรายละเอียดและขั้นตอนติดตั้งใน [supabase/SETUP.md](supabase/SETUP.md) ต้องรัน SQL และตั้ง `.env.local` ก่อนใช้งานจริง เมื่อเปิดโหมด Supabase จะไม่ใช้ข้อมูลตัวอย่างแทนข้อมูลจริง ส่วนลงทะเบียน/เช็กอิน/คำตอบ/รายงานยังต้องย้ายในขั้นถัดไป

เมื่อสร้างโปรเจกต์ Supabase แล้ว ให้คัดลอก `.env.example` เป็น `.env.local` และใส่ URL กับ publishable key ของโปรเจกต์ ค่าใน `.env.local` จะไม่ถูกเก็บใน Git

โครงนี้เปิดหน้าแรกได้โดยไม่ต้องตั้งค่า Supabase การเชื่อม Auth, Database และ Storage จะเพิ่มพร้อมฟีเจอร์ที่ใช้งานจริง

## หน้าสาธารณะและแบบสอบถาม

- `/attendee/survey` ตอบแบบสอบถามตามคำถามที่เผยแพร่
- `/attendee/survey/thanks` ขอบคุณหลังส่งคำตอบ
- `/attendee/registration-closed` ปิดรับลงทะเบียน
- `/attendee/survey/closed` ปิดรับแบบสอบถาม
- `/display` จอสาธารณะพร้อม QR ลงทะเบียนและแบบสอบถาม อัปเดตสถานะทุก 30 วินาที
- `/qr-center` เปิด–ปิดรับ และเผยแพร่รายละเอียด/คำถามที่บันทึกใน Manager
- `/report` สรุปยอดใน SQLite และคำตอบที่ส่งจริง พร้อม CSV/พิมพ์ PDF

แก้ไขและบันทึกคำถามใน `/survey` แล้วกด **เผยแพร่รายละเอียดและแบบสอบถามที่บันทึกไว้** ใน QR Center เพื่อให้เครื่องอื่นอ่านข้อมูลที่เผยแพร่จากเซิร์ฟเวอร์เดียวกันได้ การเปิด–ปิดรับบันทึกแยกได้โดยไม่เผยแพร่คำถามที่ยังแก้ไม่เสร็จ

ขณะพัฒนา (`npm run dev`) ใช้ Manager เดิม `manager@example.com` / `1234` เพื่อเผยแพร่ข้อมูลได้ การเข้าสู่ระบบนี้เป็นบัญชีสำหรับทดสอบและยังไม่แทนระบบบัญชีจริงของ Admin ใน production ต้องกำหนด `MANAGER_DEMO_PASSWORD` อย่างน้อย 16 ตัวอักษร และ `MANAGER_DEMO_SESSION_SECRET` แบบสุ่มอย่างน้อย 32 ตัวอักษรเอง จึงจะเปิดบัญชีทดสอบนี้

คำตอบและข้อมูลที่เผยแพร่เก็บในไฟล์ SQLite ตาม `SQLITE_PATH` หรือ `data/event-survey.db` ส่งซ้ำด้วยรหัสคำขอเดิมไม่เพิ่มคำตอบซ้ำ แบบสอบถามไม่ระบุตัวตน จึงไม่ได้ยืนยันตัวบุคคลหรือบังคับว่าต้องเช็กอินก่อนตอบ

ตรวจการบันทึก การปิดรับ การส่งซ้ำ และการเปลี่ยนคำถามด้วย `node scripts/test-public-event.cjs` ซึ่งใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลจริง

หน้าจอ `/display` แสดงรายละเอียดและ QR ส่วนการกระจายคิวโฆษณาไปยังอุปกรณ์จอจริงยังไม่ได้เชื่อมต่อ
