# ต้นฉบับหน้า Manager จากเพื่อน

เก็บโค้ดทั้ง 4 ไฟล์จาก commit `e29fb1e93d685c11cd7aa2608e3592ae3380f213` ไว้ครบถ้วนในไฟล์ `.tsx.md` เพื่อเปิดอ่านและนำหน้าตามาปรับต่อ โดยไม่ให้หน้าตัวอย่างที่ยังไม่พร้อมไปแทนระบบที่กำลังใช้งาน

## วิธีแก้ข้อขัดแย้งครั้งนี้

ไฟล์หลักใน `src/app/(manager)` ใช้เวอร์ชันจาก commit `290a070` ซึ่งทำงานร่วมกับโครงสร้างปัจจุบัน ส่วนต้นฉบับที่ส่งเข้ามายังคงอยู่ในโฟลเดอร์นี้และในประวัติ Git ทั้ง 4 commits

| ไฟล์ | ส่วนที่รักษาไว้ในแอปหลัก | สิ่งที่ต้องปรับก่อนนำต้นฉบับมาใช้ |
|---|---|---|
| dashboard.tsx | การแยกข้อมูลตัวอย่าง/ข้อมูล Supabase และ CloudManagerDashboard | ต่อข้อมูลจริงแทนชื่ออีเวนต์/ตัวเลขที่เขียนค้างไว้ และเชื่อมปุ่มสร้าง/แก้ไข/รายงาน |
| kiosk.tsx | อัปโหลด/ลบ/เรียงสื่อ เลือกจอ ตรวจเวลา และบันทึกการตั้งค่า | เชื่อมปุ่มและช่องเลือกจอกับ state และระบบบันทึกแทนค่าตัวอย่าง |
| registration.tsx | ค้นหา กรองสถานะ และดูข้อมูลผู้ลงทะเบียนในโหมดตัวอย่าง | ต่อช่องค้นหา ตัวกรอง ปุ่มดูข้อมูล และปุ่มแบ่งหน้าให้ทำงาน |
| report.tsx | อ่านผลแบบสอบถาม ส่งออก CSV พิมพ์ PDF และจัดการโหลด/ข้อผิดพลาด | ใช้ข้อมูลรายงานแทนตัวเลขคงที่ และเชื่อมปุ่มส่งออก |

ต้นฉบับทั้ง 4 ไฟล์เรียก `@/components/Header` และ `lucide-react` ซึ่งยังไม่มีในโปรเจกต์นี้ รวมถึงใช้ Tailwind utility classes ขณะที่หน้าปัจจุบันใช้ CSS Modules จึงต้องปรับให้เข้ากับส่วนหัว เมนู และรูปแบบของแอปก่อนใช้งานจริง

การแก้ merge นี้ไม่ได้เปลี่ยนตาราง Supabase ไม่ได้ย้ายข้อมูลตัวอย่างเข้าโปรเจกต์จริง และไม่ได้เผยแพร่เว็บ Vercel เพิ่ม ส่วนผู้ลงทะเบียน/รายงานในโหมด Supabase ยังคงสถานะรอเชื่อมข้อมูลตามขอบเขตเดิม
